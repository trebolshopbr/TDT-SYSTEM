Conservar el historial auditable de decisiones directivas y resoluciones ante excepciones escaladas.

2. REGLA APPEND-ONLY

DEC-2026-09-05-004 — CORE DATA CONTRACT / REGISTRY V0

DECISIÓN
TDT SYSTEM adopta un Core Data Contract / Registry V0 interno como proyección derivada y reemplazable del índice existente. No constituye una fuente canónica nueva ni desplaza Drive o las fuentes de dominio.

REGLAS
- identidad estable por tipo + entity_id;
- record types ENTITY / STATE / EVENT / SOURCE / DECISION;
- provenance obligatoria;
- HECHO / PERCEPCIÓN / CONTEXTO / HIPÓTESIS / DECISIÓN no se mezclan;
- certeza CONFIRMED / INFERRED / UNKNOWN;
- freshness CURRENT / STALE / UNKNOWN / ERROR;
- vigencia operativa CURRENT_STATE / AS_RECORDED / HISTORICAL / UNKNOWN se evalúa separadamente de freshness;
- decisiones requieren clasificación DECISION;
- percepciones no pueden elevarse a estado confirmado por derivación;
- Sessions/Captures sólo ingresan desde recibos confirmados sin duplicados;
- sesiones y bloques son entidades distintas.

PRINCIPIO NUEVO CONSOLIDADO
FRESHNESS DE EVIDENCIA ≠ VIGENCIA OPERATIVA.

PRIMER CONSUMIDOR APROBADO
REENTRY + DAILY SYNCHRONIZATION como proyección humana del Registry. No exponer Registry crudo o telemetría técnica a TT.

ESTADO
APROBADO · IMPLEMENTADO INTERNAMENTE · PROYECCIÓN VISUAL PENDIENTE.
